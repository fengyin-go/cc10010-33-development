# 数据湖治理配置中心

离线版数据湖治理配置工具，涵盖多源接入通道、分层表结构设计、湖区分区策略、流批转换编排、元数据编目检索与资源计量管理，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/api/settlement.ts      周期结算引擎：周期汇总、幂等结算、回退与审计
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 资源计量周期结算

「资源计量」页在计量记录清单之外提供周期结算工作台，规则如下：

- **汇总范围**：同一计费周期（`YYYY-MM`）下、状态为「待汇总」的流处理作业与批量转换任务，
  按「计算引擎」分组汇总 CPU核秒、内存GB秒、存储占用GB、扫描数据量，形成资源汇总结果。
- **已结算记录**：结算成功后记录状态变为「已结算」，并写入结算批次、结算时间；
  结算结果本身以不可变快照存放在 `lake-govern-config:settlements`，与计量记录分开持久化。
- **补录隔离**：周期一旦结算即锁定。补录到已结算周期时，记录会自动顺延进入下一周期并标记
  「补录标记=是 / 原始计费周期=原周期」，历史已结算记录与汇总快照按原周期保持不变。
- **幂等与并发**：一个周期只允许一个生效批次，重复提交返回已有批次（`DUPLICATE`），不会重复计费；
  同一周期在前端有内存锁与 `localStorage` 周期锁两重保护，并发提交直接拒绝（`BUSY`）。
- **失败回退**：结算写入中途失败（可用页面上的「模拟写入失败」按钮演练）时，参与结算的计量记录
  按结算前原行整体退回「待汇总」，结算批次与审计行都不落库，失败记录写入失败明细并在界面保留。
- **审计明细**：每次成功结算都会在「操作审计」追加一条「结算确认」日志，记录周期、批次、
  资源汇总与 ISO 周次；审计页顶部单独展示本周结算结果。
- **权限**：结算、补录登记、计量记录的汇总/归档只对「计算引擎负责人」开放；其他角色页面只读，
  越权请求在 `settlePeriod` / `registerMetering` / `runAction` 入口直接拒绝，且不写任何数据。
- **历史口径**：结算沿用原资源口径（CPU核秒 / 内存GB秒 / 存储占用GB / 扫描数据量），
  历史计费账期不重算、不换算。

角色可在顶栏切换（默认「计算引擎负责人」，可切到「值班管理员」「数据开发」验证只读行为）。

## 约定
- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `lake-govern-config:entries` 这一项，或调用 `resetModule(模块)`。
